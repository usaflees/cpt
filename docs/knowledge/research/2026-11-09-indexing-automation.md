# Automate the IndexNow push, leave Google to the owner

cryptopriceticker.com can automate only one indexing channel without account credentials, and this work has now automated it. **IndexNow reaches seven engines with one unauthenticated POST**: Bing, Yandex, Seznam, Naver, Yep, the Internet Archive and Amazon. Through Bing it also reaches Copilot, DuckDuckGo and part of ChatGPT search. **Google is not reachable by any credential-free push.** Its sitemap ping has returned 404 since late 2023, it does not take part in IndexNow, and its Indexing API is restricted to job and livestream pages. Google, and with it AI Overviews, AI Mode and Gemini, therefore depends on three owner actions: submit the sitemap in Search Console, request indexing for about ten hub URLs, and earn a few real external links. Google names "too new" and "not well connected through links from other sites" as the two most common reasons a site is not indexed. No AI answer engine accepts URL submissions from ordinary sites. Each one draws on Bing, Google, Brave or its own crawler, and the robots.txt already admits all of them. Free monitoring splits along the same line. Robots and reachability checks, IndexNow response codes, Common Crawl presence and render checks run with no account. Per-URL Google index state, Bing crawl statistics and crawler-visit counts each need one owner grant: a Search Console service account, a Bing API key or a read-only Cloudflare token. Expect weeks, not days, for Google. The evidence on what speeds indexing is official guidance plus observational vendor data, not controlled tests.

## IndexNow now runs after every deploy and sends only real changes

IndexNow is the only push channel that needs nothing but the public key file already at the site root. The official participant list names **seven engines**: Bing, Yandex, Seznam, Naver, Yep, the Internet Archive and Amazonbot. A submission to any one endpoint "will be automatically shared with all other participating search engines" ([indexnow.org searchengines.json](https://www.indexnow.org/searchengines.json), [IndexNow documentation](https://www.indexnow.org/documentation)). A POST carries up to **10,000 URLs**. An HTTP 200 means only that the request was received. A 202 means key validation is pending. A 403 or 422 means the key or host is wrong, and a 429 means too many requests ([IndexNow documentation](https://www.indexnow.org/documentation)). The protocol's main rule is restraint: "Submit only when content has changed. Do not resubmit unchanged URLs." It also asks sites to wait at least 5–10 minutes between submissions of the same URL, and it wants deleted and redirected URLs reported so engines can drop them. Per-engine daily thresholds are not published ([IndexNow FAQ](https://www.indexnow.org/faq)). Microsoft adds that IndexNow "does not guarantee that web pages will be crawled or indexed", but that engines "will generally prioritize crawling these URLs" ([Bing IndexNow](http://bing.com/indexnow/getstarted)).

Before this work, `scripts/indexnow.mjs` broke that rule on every release. It submitted every page whose HTML differed from the previous commit, so a CSS or JS change that only re-stamped the `?v=` asset hashes sent **115–131 URLs per release**, nearly the whole site. Three changes now fix this. First, the script normalises away `?v=` hashes and the inlined theme script before comparing pages, using the same rule the sitemap `lastmod` logic uses, so an asset-only release sends nothing. Second, it now includes deleted pages, as the FAQ asks. Third, a new `indexnow` job in `.github/workflows/site-checks.yml` runs after the checks job on every push to `main`. It needs no secrets and keeps `contents: read`. It waits up to ten minutes for `tests/wait-deploy.sh` to confirm that production serves the new build, then submits the pages changed since `github.event.before`. It refuses to fall back to `--all` when the previous commit is unknown (a new branch or force-push), and it carries `continue-on-error`, so it never blocks a deploy. The weekly refresh reaches production through a push to `main` too, so the same job covers it.

Polling the live site was chosen over the alternatives on purpose. A `check_run` trigger on the Cloudflare Pages GitHub App would also work without secrets, but the app's exact slug, its check-run name and whether the check completes only after the edge serves the build are all undocumented ([Cloudflare Pages GitHub integration](https://developers.cloudflare.com/pages/configuration/git-integration/github-integration/), [GitHub Actions events](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows)). Cloudflare's "Deployment success" notification webhook would need a relay Worker holding a GitHub token, which is a new credential and new infrastructure for a 131-URL site ([Cloudflare notifications](https://developers.cloudflare.com/notifications/notification-available/)).

**Two defects remain in the new job.** The submit step pipes the script into `tee` under GitHub's default `bash -e` shell, which has no `pipefail`. The step therefore always sees tee's exit code of 0. The "retry once in 60 s" branch never runs, and a 403, 422 or 429 never turns the job red. Adding `shell: bash` to the step, which turns on `pipefail`, or `set -o pipefail` at the top of the script, fixes both. Separately, CLAUDE.md and the `ship` skill still tell an agent to run `node scripts/indexnow.mjs <previous-main-sha>` by hand after a deploy. Now that the job does this, the manual run would resubmit the same URLs within minutes, inside the FAQ's 5–10 minute window. Remove the manual step, or keep it only for when the job fails.

Three related fixes from this session's live checks support indexing directly. **robots.txt no longer carries the `Content-Signal` line.** Lighthouse flagged it as an "Unknown directive", which cut the SEO score to 92, and seo-lint now rejects any unknown robots.txt directive. **About 400 `_redirects` rules now send upper-case and name forms** such as `/coin/BTC/` and `/coin/bitcoin/` to the canonical coin URL, where both used to return 404. These were never indexed, so they do not need IndexNow submission. **The duplicate-host risk does not apply.** One research note says Cloudflare's production `*.pages.dev` alias serves an indexable copy and needs a Bulk Redirect or a host-scoped noindex ([DEV](https://dev.to/playpipio/your-cloudflare-pages-site-is-on-google-twice-53j6)). The live check on 2026-11-09 found that `cryptopriceticker.pages.dev` and every preview host already return `X-Robots-Tag: noindex` with a canonical to cryptopriceticker.com, so no redirect or `_headers` rule is needed. Adding one would only risk breaking preview QA.

One overlap needs an owner decision. **Cloudflare Crawler Hints**, free on every plan, sends IndexNow signals automatically on cache MISS ([Cloudflare Crawler Hints](https://developers.cloudflare.com/cache/advanced-configuration/crawler-hints/)). Every deploy purges the cache, so Crawler Hints would report unchanged pages on top of the script's precise list. **Leave Crawler Hints off.**

## Google offers no push, so three owner clicks outweigh any script

Google retired the sitemap ping; it has returned 404 since the deprecation completed in late 2023. Google reads `lastmod` only if it "consistently match[es] reality", and it ignores `changefreq` and `priority` ([Google Search Central, June 2023](https://developers.google.com/search/blog/2023/06/sitemaps-lastmod-ping)). The site already handles the passive side. The robots.txt has a `Sitemap:` line. The build moves `lastmod` only when normalised content changes: today 126 URLs carry 2026-11-08, four carry 2026-11-06 and one carries 2026-11-09. Every hub links each coin page in plain HTML. The **Indexing API is off-limits**. It "can only be used to crawl pages with either JobPosting or BroadcastEvent embedded in a VideoObject", submissions are spam-checked, and abuse "may result in access being revoked" ([Indexing API quickstart](https://developers.google.com/search/apis/indexing-api/v3/quickstart)). No API can request indexing. The URL Inspection API is read-only, and "Request indexing" exists only in the Search Console interface.

What remains is manual and needs the owner. Submitting `sitemap.xml` once in Search Console is enough, because Google then re-fetches it on its own schedule. "Request indexing" has a **dynamic, unpublished quota**. Practitioners put it at about 10 URLs per property per day ([IndexInstantly](https://www.indexinstantly.com/blog/request-indexing-search-console-limits/)), and requests fail silently once the quota is spent ([Search Console help](https://support.google.com/webmasters/answer/10351509)). Google says "requesting a recrawl multiple times for the same URL won't get it crawled any faster" ([Ask Google to recrawl](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl)). Spend the quota on the home page and the nine sector hubs, not on the 114 coin pages. With owner-granted access, a service account added as a Full user can call `sitemaps.submit` (a bodiless PUT to `sc-domain:cryptopriceticker.com`) from a separate, secret-holding workflow ([sitemaps.submit](https://developers.google.com/webmaster-tools/v1/sitemaps/submit), [Search Console permissions](https://support.google.com/webmasters/answer/7687615)). That adds little once the sitemap is registered. Its real value is monitoring, covered in the last section. Because the repo is public, a workflow like that must never run on `pull_request` from forks.

Set expectations by Google's own numbers. "It can take a week or so for Google to start crawling and indexing a new page or site" ([Page indexing report help](https://support.google.com/webmasters/answer/7440203)). Crawling "can take anywhere from a few days to a few weeks" ([Ask Google to recrawl](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl)). Gary Illyes's internal ranges, as one attendee reported them in October 2026, put discovering a new URL at about **20 hours typically and "weeks to never" at the slow end**. Refreshing a known URL takes about 30 days typically ([Search Engine Journal](https://www.searchenginejournal.com/google-crawling-indexing-recovery-timing-ranges/591829)). Across 16 million tracked pages, IndexCheckr measured an average of **27.4 days to index**, with only 14% indexed within a week ([IndexCheckr](https://indexcheckr.com/resources/google-indexing)). For this site the bottleneck is crawl priority and quality judgment, not discovery. Google's FAQ ranks "too new" and weak external linking as the top causes ([Google crawling and indexing FAQ](https://developers.google.com/search/help/crawling-index-faq)). John Mueller warned in September 2026 that templated, programmatic pages can make Google's systems "lose faith" in a site ([Search Engine Roundtable via PikaSEO](https://pikaseo.com/articles/programmatic-seo-google-lost-faith-2026)), and that when Google is "seriously worried" about quality it will "crawl a lot less" and "index a lot less" ([Search Engine Journal](https://www.searchenginejournal.com/google-explains-seo-connection-of-site-quality-to-non-indexed-pages/582683/)). The domain was re-registered in October 2026. Google does not penalise that by default, but Mueller says a domain's old state can take "a lot of time" to be "shaken off", and that "there's nothing manual that you can / need to do" beyond checking Manual actions and Removals ([Search Engine Journal](https://www.searchenginejournal.com/google-explains-expired-domains-and-ranking-issues/557283)). Expect many of the 114 coin pages to sit at "Crawled – currently not indexed" for a while. Earned links and visibly unique data high on each coin page move that status. Repeated indexing requests do not.

Bing needs only one owner step. **Import the property from Search Console into Bing Webmaster Tools** (My Sites → Import). This verifies the site and registers its sitemaps in a few clicks, and Bing re-checks ownership through Search Console from then on ([Bing Webmaster blog](https://blogs.bing.com/webmaster/september-2019/Import-sites-from-Search-Console-to-Bing-Webmaster-Tools)). Keep the Bing URL Submission API out of automation. It needs a secret and duplicates IndexNow, which Microsoft now recommends over it ([Bing blog](https://blogs.bing.com/webmaster/2021/9/Access-to-Instant-Indexing-%C2%A0Bing%C2%A0URL-submission-API/)). Bing's anonymous sitemap ping was removed in 2022 ([Search Engine Land](https://searchengineland.com/microsoft-bing-drops-anonymous-sitemap-submission-due-to-spam-issues-385178)).

## AI answer engines draw on four indexes, and none accepts submissions

No AI answer engine documents a URL-submission channel for ordinary sites. Each draws on Bing, Google, Brave or its own search crawler, so the useful levers are getting into Google and Bing, keeping IndexNow running, and letting every search crawler in. The table maps each engine to the index it relies on and to what reaches it.

| Engine | Index it draws on | Search crawler token | What reaches it from this site |
|---|---|---|---|
| ChatGPT search | Third-party providers (Microsoft is linked in OpenAI's help page) plus its own crawler ([OpenAI Help](https://help.openai.com/en/articles/9237897-searching-the-web-with-chatgpt)) | OAI-SearchBot ([OpenAI](https://developers.openai.com/api/docs/bots.md)) | IndexNow → Bing; robots.txt allow |
| Microsoft Copilot | Bing ([Bing Webmaster Blog](https://blogs.bing.com/webmaster/2025/7/Keeping-Content-Discoverable-with-Sitemaps-in-AI-Powered-Search)) | Bingbot | IndexNow; Bing Webmaster Tools (owner) |
| Google AI Overviews, AI Mode, Gemini | Google Search index; "no additional technical requirements" ([Google](https://developers.google.com/search/docs/appearance/ai-features?hl=en)) | Googlebot | Search Console (owner); links |
| Perplexity | Own index; 65% of short-tail citations overlap Google's top 10 ([Ahrefs](https://ahrefs.com/blog/chatgpt-google-citations)) | PerplexityBot ([Perplexity](https://docs.perplexity.ai/docs/resources/perplexity-crawlers)) | robots.txt allow; Google indexing |
| Claude | Brave (strong secondary evidence, unconfirmed) ([Noetio](https://noetio.com/blog/how-claude-web-search-works)) plus its own crawler | Claude-SearchBot ([Claude Help Center](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-the-web)) | Brave follows Googlebot's robots rules |
| Brave Search, Leo | Independent Brave index ([Brave](https://search.brave.com/help/brave-search-crawler)) | No distinct user agent | search.brave.com/submit-url (manual) |
| Apple Siri, Spotlight | Applebot; links from other pages are a ranking factor ([Apple](https://support.apple.com/en-us/119829)) | Applebot | robots.txt allow; links |
| Amazon Alexa+, Rufus | Own crawlers ([Amazon](https://developer.amazon.com/en-US/amazonbot)) | Amzn-SearchBot, Amazonbot | IndexNow (Amazonbot participates) |
| Meta AI | Own index under construction ([Meta](https://developers.facebook.com/documentation/sharing/webmasters/web-crawlers)) | Meta-WebIndexer | robots.txt `*` group |
| DuckDuckGo, DuckAssist | "Largely" Bing plus DuckDuckBot ([DuckDuckGo](https://duckduckgo.com/duckduckgo-help-pages/results/sources)) | DuckAssistBot | IndexNow → Bing |

Three patterns follow from the table. First, **Search Console is the single largest unlock**: it gates Google's AI features directly and correlates strongly with Perplexity's citations. 76% of AI Overview citations come from top-10 pages ([Ahrefs](https://ahrefs.com/blog/ai-search-overlap)). Second, **IndexNow already feeds the Bing-dependent engines and Amazon**. Microsoft says it "helps ensure that AI systems reference the most current version of a page" ([AI Rank Lab, quoting Bing](https://www.airanklab.com/blog/microsoft-copilot-seo)), but that is a vendor statement, not a measured effect. Third, the robots.txt's single shared group already admits every documented search crawler. Meta-WebIndexer, Amzn-SearchBot and MistralAI-Index are admitted through `User-agent: *` without being named. Naming them would only document the policy. Removing the `*`/Googlebot line would silently lock Brave out, because Brave's crawler "will not crawl" what Googlebot cannot ([Brave](https://search.brave.com/help/brave-search-crawler)).

The files that vendors promote for AI do little. In Ahrefs' study of 137,210 domains, **97% of published llms.txt files received zero requests** ([Ahrefs](https://ahrefs.com/blog/llmstxt-study/)). Google says AI features need no "new machine readable files, AI text files, or markup" ([Google](https://developers.google.com/search/docs/appearance/ai-features?hl=en)). Keep the existing llms.txt because it costs nothing, and spend no more effort on it. An Atom feed is cheap, and Mueller has seen unnamed AI crawlers fetch RSS files ([Search Engine Journal](https://www.searchenginejournal.com/googles-mueller-says-ai-crawlers-access-sitemaps-rss-in-his-logs/592012)). No AI vendor documents reading feeds, though, and price-only changes don't belong in one. Skip the feed until real editorial content exists. Common Crawl publishes about one crawl a month of about 2.2 billion pages. It samples the web by link-graph centrality, takes no inclusion requests and reads the robots.txt sitemap ([Common Crawl FAQ](https://commoncrawl.org/faq), [Common Crawl About](https://www.commoncrawl.org/about)). It shapes future model training, not live answers, and again only links move it. A Wikidata item or Wikipedia article about the site would breach notability and self-promotion rules until independent coverage exists ([Wikidata:Self-promotion](https://www.wikidata.org/wiki/Wikidata%3ASelf-promotion)).

Freshness matters most for ChatGPT, which cites URLs **458 days newer** than Google's organic results ([Ahrefs](https://ahrefs.com/blog/do-ai-assistants-prefer-to-cite-fresh-content)). Every engine, though, quotes the version it fetched, and live fetchers such as ChatGPT-User, Claude-User and Perplexity-User mostly do not run JavaScript. What they can quote is the dated build-time snapshot in the static HTML, not the live browser price. That makes honest `lastmod` values and precise IndexNow submissions the freshness mechanism, which is exactly what the corrected script now provides. New domains see AI search crawlers slowly. One log of a brand-new domain recorded **zero OAI-SearchBot and PerplexityBot visits in the first 75 hours**, against 230 Googlebot requests ([AI Visibility Census](https://dev.to/censusadmin/do-ai-crawlers-read-llmstxt-what-three-days-of-server-logs-show-gpn)).

## Free monitoring: four checks run without accounts, three owner grants add the rest

Monitoring falls into three tiers. The first runs today with no account. The second needs an owner-granted credential. The third is owner-only dashboards that need no automation. All results are telemetry under the project's rules, so they belong in job summaries or the private `usaflees/cpt-telemetry` repo, never in this public repo.

| Monitor | Credential | What it answers | Cost and limits |
|---|---|---|---|
| IndexNow job summary | None (already live) | Whether each submission returned 200/202, and how many URLs it sent | Needs the `pipefail` fix to report failures |
| Robots and reachability check | None | Whether robots.txt admits each documented token and key URLs return 200 to each bot's user agent | Cannot see Cloudflare IP-based bot blocking |
| Common Crawl CDX query | None | Whether `cryptopriceticker.com/*` appears in the latest monthly crawl | Monthly; the site cannot be in crawls before November 2026 ([Common Crawl](https://www.commoncrawl.org/blog/october-2026-crawl-archive-now-available)) |
| Headless render check | None | Whether the snapshot price, stats, canonical and JSON-LD exist in rendered HTML | Mirrors, not equals, Googlebot's renderer |
| URL Inspection API | Service account as Full user in Search Console (owner) | Per-URL coverage state, last crawl time, Google-selected canonical | 2,000 per day per site; 131 URLs fit daily ([Search Console API limits](https://developers.google.com/webmaster-tools/limits)) |
| Bing Webmaster API | API key from Bing Webmaster Tools (owner) | GetUrlInfo per URL; GetCrawlStats for six months ([Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/api/microsoft.bing.webmaster.api.interfaces.iwebmasterapi?view=bing-webmaster-dotnet)) | Free; one key per user |
| Cloudflare GraphQL Analytics | Read-only Zone Analytics token (owner) | Crawler requests by user agent, verified-bot category, path and status | 31 days retention on Free since Oct 2026, so save weekly snapshots ([Cloudflare changelog](https://developers.cloudflare.com/changelog/post/2026-10-02-30-days-analytics-on-every-plan/)) |

The **URL Inspection API is the main metric worth building**. A weekly job can inspect all 131 sitemap URLs, group them into coins, sectors and tools, and write a line such as "coins: 37 indexed / 52 crawled-not-indexed / 25 discovered" to the summary. That is the clearest early signal of whether Google's quality judgment is holding back the templated pages. The service-account key should be a GitHub secret, used only in a workflow that never runs on fork pull requests, or replaced by Workload Identity Federation. The Sitemaps API's per-sitemap `indexed` count is deprecated ([Sitemaps API reference](https://developers.google.com/webmaster-tools/v1/sitemaps)), so per-section ratios come either from this script or from the Search Console UI. A sitemap index split into coins, sectors and other pages lets the owner filter the Page indexing report by section. Mueller says such a split gives "no technical advantage" for indexing, only readable stats ([Search Engine Roundtable](https://www.seroundtable.com/google-split-xml-sitemap-files-21341.html)). It is optional, and the children must be submitted one by one to appear in the filter ([Page indexing report help](https://support.google.com/webmasters/answer/7440203)). Do not automate `site:` queries. Google says they do not return all indexed URLs ([Google](https://developers.google.com/search/docs/monitor-debug/search-operators/all-search-site)), and scraping results breaks its terms.

The owner-only dashboards are free and cover AI citation directly. Cloudflare **AI Crawl Control** on Free shows per-crawler request counts by user agent for the past 24 hours. Its referral views are paid-only ([Cloudflare](https://developers.cloudflare.com/ai-crawl-control/features/analyze-ai-traffic)). The **Search Console Generative AI report**, open to all sites since 31 August 2026, shows AI Overviews and AI Mode impressions by page, without queries ([Search Console Help](https://support.google.com/webmasters/answer/16984139?hl=en)). Bing's **AI Performance** report shows Copilot citations and grounding queries, refreshed daily ([Search Engine Journal](https://www.searchenginejournal.com/bing-webmaster-tools-adds-ai-citation-performance-data/566874)). For referrals, Cloudflare Web Analytics lists top referrers for free, and ChatGPT tags its links with `utm_source=chatgpt.com` ([OpenAI FAQ](https://help.openai.com/en/articles/12627856-publishers-and-developers-faq)). Claude's native app sends no Referer header, so AI referrals are undercounted ([Citepoint](https://citepoint.ai/articles/ai-search-statistics)). GA4 excludes bots, so it cannot count crawlers.

## What remains for the owner, in order of impact

Each item below needs an account this session does not hold. Each takes minutes, and none costs money. First, in **Search Console**, submit `https://cryptopriceticker.com/sitemap.xml`. Request indexing for `/` and the nine sector hubs, and only those. Check Manual actions, Security issues and Removals once, because the domain was re-registered. Second, in **Bing Webmaster Tools**, import the property from Search Console. That also opens the IndexNow submission log and the AI Performance report. Third, in **Cloudflare**, open Security → Bot traffic and confirm that the AI bot policies allow Search, Agent and Training and that Bot Fight Mode is off. Cloudflare's September 2026 policy changes can block search crawlers on migrated zones ([Cloudflare blog](https://blog.cloudflare.com/accountable-mixed-use-ai-crawlers/)), and the repo-side reachability check cannot see IP-based blocks. Leave Crawler Hints off.

Fourth, to unlock automated monitoring, grant any of three read-only credentials. A Google Cloud service account added as a Full user on `sc-domain:cryptopriceticker.com` enables the URL Inspection report. A Bing Webmaster API key enables GetUrlInfo and GetCrawlStats. A Cloudflare token limited to Zone Analytics Read enables crawler-visit counts. Store them as GitHub secrets on non-fork workflows, or as read-only Claude connectors. Fifth, optionally submit the home page at search.brave.com/submit-url. Brave documents that form only for re-fetching and delisting, so treat it as a low-value one-off. Sixth, and most important over months, **earn independent links and mentions** from crypto directories, GitHub READMEs and community posts. Links are Google's second-listed indexing factor, an explicit Apple ranking factor and the only lever for Common Crawl priority. Two repo-side follow-ups do not need the owner: add `pipefail` to the IndexNow step, and drop the manual IndexNow step from CLAUDE.md and the `ship` skill.

## Conclusion

The automation that was possible without credentials is now done, and its most important property is restraint, not speed. A script that resubmitted nearly the whole site on every CSS release was teaching IndexNow engines to discount the site's signals, just as an inflated `lastmod` teaches Google to ignore the sitemap. From here, more automation buys almost nothing. Faster indexing will come from the owner's four or five console clicks and from earned links. Search Console matters most, because it is the gateway to Google's index and, through it, to AI Overviews, AI Mode, Gemini and much of Perplexity.

The most useful thing to build next is not another submission channel but the weekly URL Inspection report. On a re-registered domain with 114 templated pages, the risk is not that Google never finds the pages. The risk is that it finds them and declines to index them. Only per-URL coverage states will show early whether the coin pages are winning that quality judgment, and that is what should decide where content effort goes.
